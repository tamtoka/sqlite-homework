# Домашнее задание: SQLite и DBeaver

## Запуск

1. Из корня проекта выполните `python code/seed.py`. Нужен только Python 3, без сторонних библиотек. Если `shop.sqlite3` уже есть, этот шаг пропустите: генератор защищает её от перезаписи.
2. В DBeaver: **Новое соединение → SQLite → Path / Файл базы данных** → выберите `shop.sqlite3` из этой папки. При первом подключении DBeaver может предложить скачать драйвер.
3. Откройте `sql/queries.sql`, привяжите редактор к этому соединению. Выполните весь скрипт (**Alt+X** в стандартной раскладке DBeaver) либо выделяйте отдельные блоки и выполняйте **Ctrl+Enter**.
4. Выполните `python code/security_demo.py` для демонстрации SQL-инъекции и защиты через `?`.

Готовая база в комплекте уже содержит результат выполнения `queries.sql`: **134 товара и 36 заказов**. Скрипт можно запускать повторно: артикулы уникальны, вставки пропускают существующие строки, скидка вычисляется от базовой цены. Для показа вставок с нуля создайте отдельную базу: `python code/seed.py --db fresh.sqlite3` и подключите её в DBeaver.

## Что здесь

`products` хранит артикул (`sku`), название, категорию, текущую и базовую цены, остаток и признак тестового товара. `orders` хранит одну товарную позицию заказа: товар, количество, цену покупки и дату. Внешний ключ не позволяет удалить товар, на который есть заказы. Проверка внешних ключей включается отдельно для каждого соединения (`PRAGMA foreign_keys = ON`).

Начальные данные: 6 категорий по 20 товаров, 36 заказов. Три ручных INSERT добавляют два обычных и один тестовый товар, массовый INSERT добавляет 12 блокнотов; DELETE удаляет только тестовую строку. Итого: 120 + 3 + 12 − 1 = 134.

Цена покупки в `orders.unit_price` сохраняет историю: скидка на товар не меняет суммы прошлых заказов. Для учебного примера цены представлены `REAL` и округляются при выводе; в реальной финансовой системе стоит хранить целые копейки.

## Как объяснить запросы

- `WHERE` отбирает строки до группировки; `HAVING` отбирает уже сформированные группы.
- `ORDER BY price DESC LIMIT 10` возвращает десять самых дорогих из отобранных товаров.
- `JOIN` связывает `orders.product_id` и `products.id`; `SUM(quantity * unit_price)` считает выручку.
- `UPPER(sku) LIKE UPPER('abc%')`: `%` означает любое продолжение; встроенный `UPPER()` SQLite корректно работает с латиницей ASCII, но не делает регистронезависимым поиск по кириллице.
- В конкатенации SQL ввод может превратиться в условие `OR 1=1`. С placeholder `?` тот же ввод остаётся обычным значением. Параметр задаётся кортежем `(value,)`, включая запятую.
